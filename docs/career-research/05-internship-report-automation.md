## 二、版本 A：投 AI 应用 / Agent 开发岗（AI 与数据自动化前置）

> **Meiyume ｜ 货代报表自动化系统（Report Automation）**（实习 ｜ 2026.06–至今）
> 船期追踪自动化平台：14 家船司网站数据抓取 → 标准化 → Excel 报告回填，服务供应链 Sourcing 团队
>
> - **反爬与浏览器自动化攻坚**：针对 14 家异构船司站点（SPA/整页导航/API/验证码各异）定制抓取策略——ZIM 用真 Chrome channel + API 预热 + 页面上下文 XHR 绕过 Cloudflare 与 CORS；WHL 导出真人登录 Cookie（CDP/DPAPI 双路径）复用信誉跳过验证码；ONE 网站改版后补全事件映射恢复数据链路——沉淀「数据加载机制 → 等待策略」决策矩阵
> - **爬虫稳定性重构**：系统性清理 11 家船司脚本 142 处固定盲等（`wait_for_timeout`），替换为条件驱动等待（接口响应拦截/元素出现/AJAX 行数稳定判定）；多候选选择器用 `or_()` 合并单次等待，消除最坏 22s 的串行探测——抓取由「碰运气」变为「可判定成功失败」
> - **AI 发票识别工作台（F&A）**：参与 AI 提取 + 人工双控过账的前端实现——AI 识别字段旁展示**置信度**（服务端平行 confidence 结构 + 无置信度兜底，防脏数据白屏），PDF 分屏对照 + AI vs 人工逐字段比对的可解释设计
> - **离线部署工程化**：内网 Windows 服务器零网络部署——pip 离线 wheelhouse + Playwright 离线浏览器；**配置外置**（12-Factor）消除「测试/生产两套包」；定位并修复部署双重前缀导致的登录 404（构建产物 diff 锁定根因）
> - **质量闭环使用与演进**：基于「程序 vs 手工全列对比 → 人工反馈落库 → 监控看板观测」的数据质量闭环迭代抓取规则；调研 11 家船司官方 API，产出「弃爬改 API」三梯队演进方案（8 家有 DCSA 标准接口）

## 四、为什么这样写（依据链）

- **可信度第一性**：02 号调研「真实实习永远比个人项目更有说服力」（第一层证据）——实习 bullet 必须是「本人动作」可追溯的，故先立归属表，监控看板等他人主导成果不冒领（雷区 6「我们式混写」+ 07「个人职责与规模不匹配」）
- **接手型项目的正确姿势**：不写「搭建了系统」，写「在既有系统上做了什么改变」——142 处优化、反爬攻坚、部署工程化都是「没有我这部分会不一样」的可辩护差异
- **AI 岗对齐**：反爬攻坚本质是「非确定性外部系统的容错设计」，与 Agent 工具调用同构（JD 措辞「工具异常处理」可迁移）；DocAgent 工作台命中「AI 提取 + 人工确认」场景
- **后端岗对齐**：缓存语义（防毒化）/观测面解耦/配置驱动——这些是货真价实的数据工程实践，比「用了 FastAPI」高一个层级
- **踩坑弹药**（面试主打三选一）：① ZIM「requests 直调 403 → page.evaluate XHR 借页面 origin 绕 CORS + 预热拿 cf_clearance」② 部署「相对路径变双重前缀 → 登录 404，diff 锁定单行根因」③ ONE「网站改版事件名变更 → type_mapping 缺 key，对照截图补映射」
