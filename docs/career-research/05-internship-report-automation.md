## 二、版本 A：投 AI 应用 / Agent 开发岗（AI 与数据自动化前置）

> **利臻咨询服务中心（Digital Team）｜ 货代报表自动化系统（Report Automation）**（实习 ｜ 2026.06–至今）
> 船期追踪自动化平台：14 家船司网站数据抓取 → 标准化 → Excel 报告回填，服务 Meiyume Sourcing 团队
>
> - **反爬与浏览器自动化攻坚**：针对 14 家异构船司站点（SPA/整页导航/API/验证码各异）定制抓取策略——OOCL 的 Cloudflare Turnstile 嵌套跨域 iframe + Shadow DOM，DOM 方案不可达，改用 **OpenCV 视觉模板匹配**定位复选框 + 三层回退链；ZIM 用真 Chrome channel + API 预热 + 页面上下文 XHR 绕过 Cloudflare 与 CORS；WHL 导出真人登录 Cookie（CDP/DPAPI 双路径）复用信誉跳过验证码——沉淀「数据加载机制 → 等待策略」决策矩阵
> - **爬虫稳定性重构**：系统性清理 11 家船司脚本 142 处固定盲等（`wait_for_timeout`），替换为条件驱动等待（接口响应拦截/元素出现/AJAX 行数稳定判定）；多候选选择器用 `or_()` 合并单次等待，消除最坏 22s 的串行探测——抓取由「碰运气」变为「可判定成功失败」
> - **AI 发票识别 + 人工双控工作台（F&A）**：参与多模态提取 → Maker/Checker 双控 → 7 态状态机的 AI 落地范式；**主导前端可解释交互**——AI 字段旁展示置信度（服务端平行 confidence 结构 + 无置信度兜底防白屏）、PDF 分屏对照与 AI vs 人工逐字段比对
> - **工作流自动化（n8n × SharePoint）**：部门内首次打通 n8n 与 SharePoint 文件链路——无管理员权限下走 OAuth2 委托权限 + 管理员审批；REST 按路径下载（绕开内置节点级联选择器）+ 内置节点上传（支持动态文件名）混合路线；定位「内置节点与 HTTP Request 认证 audience 不一致」的隐蔽坑
> - **离线部署与长任务工程化**：内网 Windows 零网络部署（离线 wheelhouse + 配置外置消除两套包，修复部署双重前缀登录 404）；实现子进程 + 日志文件的长任务模型（重启不丢任务记录、PROGRESS 标记驱动进度条、产物按 result_id 归档 + 7 天自动清理）
> - **质量闭环与演进**：基于「程序 vs 手工全列对比 → 人工反馈落库 → 监控看板观测」的数据质量闭环迭代抓取规则；调研 11 家船司官方 API，产出「弃爬改 API」三梯队演进方案（8 家有 DCSA 标准接口）

## 四、为什么这样写（依据链）

- **可信度第一性**：02 号调研「真实实习永远比个人项目更有说服力」（第一层证据）——实习 bullet 必须是「本人动作」可追溯的；贡献三层分级（🟢 主导 / 🟡 辅助 / 既有接手），主导写「做了」、辅助写「参与」、接手写「在既有系统上」——既不冒领也不自贬
- **接手型项目的正确姿势**：不写「搭建了系统」，写「在既有系统上做了什么改变」——142 处优化、反爬攻坚、部署工程化都是「没有我这部分会不一样」的可辩护差异
- **AI 岗对齐**：反爬攻坚本质是「非确定性外部系统的容错设计」，与 Agent 工具调用同构；OOCL OpenCV 视觉方案展示「DOM 不可达时换范式」的工程判断；DocAgent 工作台命中「AI 提取 + 人工确认 + 可解释」三要素（正是 02 号调研「AI 项目要写评估与可控性」的要求）
- **后端岗对齐**：子进程异步任务模型 / 分桶缓存防毒化 / 观测面解耦 / 产物治理——真实数据工程实践，比「用了 FastAPI」高一个层级
- **踩坑弹药**（面试主打四选一）：① ZIM「requests 直调 403 → page.evaluate XHR 借页面 origin 绕 CORS + 预热拿 cf_clearance」② OOCL「跨域 iframe + Shadow DOM 双重封死 → OpenCV 视觉模板匹配换范式」③ 部署「相对路径变双重前缀 → 登录 404，diff 锁定单行根因」④ n8n「内置节点与 HTTP Request 的 token audience 不一致 → 401 Invalid audience，按 API 受众选路线」
